# agentql-quest

**AgentQL Quest** is a retro text-adventure version of the
[Learn AgentQL course](../../agents/cli/ts-object-model-agentql-query/references/learning-path.md),
played in the browser. It teaches one idea: the AI only understands the question and writes it
as AgentQL, and ThoughtSpot compiles that AgentQL against the Model into the same governed
warehouse SQL every time.

Published to GitHub Pages at **`/agentql-quest/`** of the repo's site by
[`.github/workflows/pages.yml`](../../.github/workflows/pages.yml) on every merge to `main` that
touches this directory or the lesson capture. The site's home page, which lists it, is
[`.github/pages/index.html`](../../.github/pages/index.html).

## Two paths

| Hero | For | What they do |
|---|---|---|
| The Queen / The King | Account reps and anyone who needs the summary | Judge claims brought to court ("the AI runs SQL against our warehouse") as true or false |
| Dwarf Warrior | Data engineers and anyone who reads SQL | Fight a dragon made of the generated SQL. Each scale is a line of it; break it by saying who put it there: ThoughtSpot (from the Model or its own rules), the AgentQL, or the AI (which never writes the SQL that runs) |
| Elf / Human Warrior | Analysts / SEs | Sealed until an encounter lists them in `paths` |

## How it is built

```
encounters.yaml ─┐
lesson-sql.md ───┼─► build.py ─► index.html  (one self-contained file)
game.html ───────┤
fonts/ ──────────┘
```

- **`lesson-sql.md`** (in the skill's `references/`) is the only source of SQL: the AgentQL and
  the `executable_sql` captured live by `tools/agentql-retest --suite lessons guards` and
  generated by `tools/agentql-retest/build_lesson_sql.py`. The game never carries a copy.
- **`encounters.yaml`** holds what the capture can't: which SQL lines to ask about (matched as
  whole lines, never by line number), facts about the whole statement (`sql_count`), who put
  each one there, and the words shown.
- **`game.html`** is the page with `__QUEST_DATA__` and `/*__FONT_FACES__*/` placeholders.
  `build.py` writes the data and the fonts into it, so the page makes **no outside requests**
  and runs from Pages, any static host, or a double-click.
- **`fonts/`** holds the Latin subsets of VT323 and IBM Plex Mono (Fontsource 5.3.0), with
  their SIL Open Font License files.

```bash
python3 tools/agentql-quest/build.py                      # → tools/agentql-quest/dist/index.html
python3 tools/agentql-quest/build.py --check              # validate only
python3 tools/validate/check_agentql_quest.py --root .    # the same, as pre-commit and CI run it
pytest tools/agentql-quest/tests -q                       # includes a headless play-through (needs node)
```

## When the build fails

`build.py` refuses to build when the encounters no longer match the capture:

| Error | Meaning | Fix |
|---|---|---|
| `<case>: not in lesson-sql.md` | the case id was renamed or dropped | update `case:` |
| `captured status was not SUCCESS` | the lesson now fails to compile | the lesson changed; pick another case or fix the lesson |
| `agentql differs from the captured AgentQL` | the query changed, not just its layout | copy the new AgentQL from `lesson-sql.md` |
| `no SQL line is exactly '…'` | a recapture changed that line of the generated SQL | re-read the new SQL; update the point, **and its lesson text if the behaviour moved** (a changed row cap or join type means the lesson is now wrong, not just the highlight) |
| `expected '…' N time(s) in the SQL` | a whole-statement fact moved, e.g. the fact table is read twice (pruning off) | same: check whether the lesson still holds |
| `match '…' hits no line` | a `scroll` substring no longer appears in the AgentQL | update `scroll` |

## Adding an encounter

Add an entry under `encounters:` keyed by a lesson's **Guarded by** case id, with the `paths`
it appears on, a `quest`, the AgentQL laid out for reading, and its `points`. A `who` point
names its `answer` (`model`, `thoughtspot` or `agentql`) and must highlight `sql`; a `choice`
point lists its own `options` with exactly one `correct: true`. `scroll: []` highlights nothing
in the AgentQL, which is itself the clue that ThoughtSpot added the line.

Every lesson text must be true of the captured SQL and match the course. Write numbers that
the capture can't hold (row counts, product names) as the course's taught numbers and say so
on screen. Prove a new point with a recapture variant in `tests/` that makes it false and
fails the build.
