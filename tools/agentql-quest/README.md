# agentql-quest

**AgentQL Quest** is a retro text-adventure version of the
[Learn AgentQL course](../../agents/cli/ts-object-model-agentql-query/references/learning-path.md),
played in the browser. It teaches one idea: the AI only understands the question and writes it
as AgentQL, and ThoughtSpot compiles that AgentQL against the Model into the same governed
warehouse SQL every time.

Published to GitHub Pages by [`.github/workflows/pages.yml`](../../.github/workflows/pages.yml)
on every merge to `main` that touches this directory or the lesson capture.

## Two paths

| Hero | For | What they do |
|---|---|---|
| The Queen / The King | Account reps and anyone who needs the summary | Judge claims brought to court ("the AI runs SQL against our warehouse") as true or false |
| Dwarf Warrior | Data engineers and anyone who reads SQL | Fight a dragon made of the generated SQL. Each scale is a line of it; break it by saying who put it there: ThoughtSpot (from the Model), the AgentQL, or the AI (never) |
| Elf / Human Warrior | Analysts / SEs | Sealed until an encounter lists them in `paths` |

## How it is built

```
encounters.yaml ─┐
                 ├─► build.py ─► index.html  (one self-contained file)
lesson-sql.md ───┘     │
game.html ─────────────┘
```

- **`lesson-sql.md`** (in the skill's `references/`) is the only source of SQL: the AgentQL and
  the `executable_sql` captured live by `tools/agentql-retest --suite lessons guards` and
  generated by `tools/agentql-retest/build_lesson_sql.py`. The game never carries a copy.
- **`encounters.yaml`** holds what the capture can't: which parts of the SQL to ask about
  (matched by substring, not line number), who put each one there, and the words shown.
- **`game.html`** is the page with a `__QUEST_DATA__` placeholder. `build.py` writes the data
  into it, so the output runs from Pages, any static host, or a double-click.

```bash
python3 tools/agentql-quest/build.py                      # → tools/agentql-quest/dist/index.html
python3 tools/agentql-quest/build.py --check              # validate only (pre-commit + CI)
pytest tools/agentql-quest/tests -q
```

## When the build fails

`build.py` refuses to build when the encounters no longer match the capture:

| Error | Meaning | Fix |
|---|---|---|
| `<case>: not in lesson-sql.md` | the case id was renamed or dropped | update `case:` |
| `captured status was not SUCCESS` | the lesson now fails to compile | the lesson changed; pick another case or fix the lesson |
| `agentql differs from the captured AgentQL` | the query changed, not just its layout | copy the new AgentQL from `lesson-sql.md` |
| `match '…' hits no line` | a recapture changed the generated SQL | re-read the new SQL and update the point (and its lesson text, if the behaviour moved) |

## Adding an encounter

Add an entry under `encounters:` keyed by a lesson's **Guarded by** case id, with the `paths`
it appears on, a `quest`, the AgentQL laid out for reading, and its `points`. A `who` point
names its `answer` (`model`, `thoughtspot` or `agentql`); a `choice` point lists its own
`options` with exactly one `correct: true`. `scroll: []` highlights nothing in the AgentQL,
which is itself the clue that ThoughtSpot added the line.
